ChainDraw — Validation Sprint 2 (Farcaster pivot)

Re-validation after channel pivot: Farcaster-first (covers Base App), Mastodon retained · 2026-08-15 · prior verdict: PIVOT (0.6)

Verdict: GO — confidence 0.75

The pivot fixes the failed dimension. On Farcaster, giveaway mechanics are native behavior, not a culture violation: the protocol itself pays weekly USDC engagement rewards, airdrop/quest culture is entrenched, and multiple giveaway tools already exist and get used. Demand score moves from 1/3 to 2–3/3. Go criteria met: 5 of 5. Conditions: differentiate on the trust story (on-chain commitment + Solana payouts) rather than raw raffle mechanics, and package as a mini-app for Base App distribution.

Demand signals (concrete, per rubric)

  • People already hack together versions of this — Cast Picker (ETHGlobal project; like+follow entry, on-chain raffle record via IPFS, in-frame draws) and its live frame. Per the rubric, "hacking together a manual version" is a top-tier signal.
  • Multiple independent teams shipped in the niche — Superchain Raffle mini-app runs weekly OP-token raffles with automatic entry via the Farcaster mini-app.
  • There is platform-level budget behind engagement — Farcaster pays weekly USDC rewards to top-engaging accounts (to Base wallets), and quest/airdrop mechanics are the ecosystem's default growth playbook. Giveaways are a native primitive here, not spam.
  • Solana-side gap persists — sprint 1 established no live Solana product does free social-engagement giveaways (existing players are paid-ticket raffles).

Integration-first assessment

  • Farcaster adapter = pure integration: Neynar REST (cast lookup, reactions, follows, verified addresses) + SIWF auth. No on-chain program work.
  • Base App reach = packaging, not code: publish a mini-app manifest (/.well-known/farcaster.json) so ChainDraw event pages render as mini-apps in Warpcast/Base App feeds. Follow-up task, not a blocker.
  • Keep Mastodon adapter untouched; introduce a platform seam in schema + server functions.

Build-phase plan (approved scope)

  • Schema migration: platform column, Farcaster cast fields, relax Mastodon-specific NOT NULLs.
  • farcaster.server.ts: Neynar client — cast resolution, likes/recasts/follow checks, verified Solana address lookup.
  • Sign In With Farcaster: client auth flow + server signature verification + signed session cookie (mirrors the Mastodon session machinery).
  • Join + create flows branch on platform; entrant wallet auto-filled from verified address on Farcaster.
  • Parallel (human): 5 organizer conversations in Farcaster channels; dogfood one real giveaway after the adapter ships.
